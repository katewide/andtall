# andtall — хэштеги задач за период

Код перенесён из AItags-main. Приложение предназначено для ручной массовой обработки исторических задач. Исходящий вебхук Битрикс24 не требуется.

## Запуск

Node.js 20+; `npm install`, затем экспортировать переменные из `.env.example` с реальными значениями и выполнить `npm start`. Файл .env автоматически не загружается. `BASE_URL` — адрес VibeCode API (например, `https://vibecode.bitrix24.tech`); сервер добавляет `/v1` сам. Ключ `API_KEY` должен иметь доступ к чтению задач, групп, контекста/медиа и AI, а также к записи тегов.

`GET /` — проверка доступности, `GET /debug` — диагностика (доступ ограничивать на уровне инфраструктуры). `npm test` — автономные тесты с подменой внешнего API.

## Массовая обработка: /ai-test

1. Открыть `/ai-test` на работающем сервере.
2. Указать начальную и конечную даты **закрытия задачи** (`closedDate` / `CLOSED_DATE`). Обе даты включены целиком, часовой пояс — Москва (UTC+3).
3. Нажать «Найти задачи». Этот шаг только читает данные, без AI и записи тегов. Просмотреть отбор; список постраничный, по 100 задач.
4. Нажать «Установить теги». Обработка идёт последовательно в фоне, с результатом по каждой задаче, счётчиками обновлений, пропусков и ошибок. Ошибка одной задачи не останавливает остальные.

Закрытие вкладки не останавливает работу. «Восстановить последний запуск» возвращает прогресс: в localStorage хранится только ID запуска. «Остановить» прекращает работу после текущей задачи, сохраняя выполненные записи. Удаление отбора из истории не удаляет теги задач.

### Ограничения отбора

- Отбор только по дате закрытия в выбранном периоде; текущий статус задачи не проверяется, в том числе у повторно открытых задач.
- Исключены исходные группы тегирования: **12, 58, 92, 140, 376, 490**.
- Исключены группы с «коллаб» в названии без учёта регистра. Название дополнительно читается через `/workgroups/:id`. Непроверенная группа не допускается к записи. Если карточка группы возвращает 404, её задачи пропускаются с причиной «Группа недоступна или не найдена (404)», а отбор продолжается. Такой результат кешируется только на время текущего отбора; перед обработкой и записью группа проверяется заново. Ошибки авторизации, таймауты и ограничения API не маскируются под отсутствующую группу.
- Задачи без группы (`groupId: 0`) допускаются, как в исходном сценарии тегирования. Список исключений мониторинга открытых задач не применяется к тегированию.
- **`UF_TASK_SUMMARY` не требуется и не проверяется в массовом сценарии.** AI использует исходную задачу и контекст; запись меняет только поле тегов.
- Перед AI и перед записью повторно проверяются дата закрытия и группа. Если задача изменилась и перестала подходить, она пропускается. Перед записью повторно читаются текущие теги, чтобы сохранить ручные.

Отбор использует `POST /v1/tasks/search`, фильтры `closedDate.$gte` / `$lt` (начало следующего дня), `groupId.$nin`, сортировку `id asc`, `autoWindow: false`, страницы по 50 и `meta.hasMore`. Неполная или зациклившаяся выдача прерывает отбор без записи. Максимум 50 000 найденных задач на отбор: при превышении нужно сузить период.

### API

Отдельного ключа запуска и заголовка `X-Tagging-Token` нет. Доступ к странице и `/tagging/*` определяется доступом к приложению на уровне хостинга; встроенной авторизации эти маршруты не выполняют. `API_KEY` остаётся на сервере и используется только для запросов к VibeCode.

| Метод и маршрут | Назначение |
|---|---|
| `POST /tagging/select` | JSON `{"from":"2025-09-01","to":"2025-09-30"}`; ответ 202 с `job_id` |
| `GET /tagging/status?jobId=...&offset=0` | Статус, счётчики, до 100 задач и результатов |
| `POST /tagging/start?jobId=...` | Записать теги для готового отбора; повторный запуск running/completed идемпотентен |
| `POST /tagging/cancel?jobId=...` | Остановить после текущей задачи |
| `DELETE /tagging/job?jobId=...` | Удалить неактивный отбор из памяти |

Одновременно выполняется один отбор или одна обработка на процесс. До 10 сохранённых запусков; при создании нового удаляются неактивные записи старше 24 часов. Состояние находится **в памяти процесса**: перезапуск прерывает запуск и теряет историю, уже записанные теги остаются. Для нескольких экземпляров потребуется общее хранилище и очередь. Таймаут одной задачи — 180 секунд; результат каждой записи проверяется повторным чтением API. Изменения между последней проверкой и PATCH нельзя исключить атомарно — API не предоставляет условную запись здесь.

Документация: [поиск задач](https://vibecode.bitrix24.tech/docs-content/entities/tasks/search.md), [фильтры](https://vibecode.bitrix24.tech/docs-content/filtering.md).

## Webhook и отключённые сценарии

По умолчанию `/webhook` отключён (404), `WEBHOOK_TOKEN` не нужен для старта сервера. Только при явном задании `WEBHOOK_TOKEN` включается сохранённый обработчик: `POST /webhook` реагирует на `ONTASKUPDATE` с изменением `UF_TASK_SUMMARY` и проверяет `auth.application_token`. Здесь исходная проверка заполненного итога сохранена. AI-промпт и справочник — `task-tagging.md`, `task-taxonomy.json`. Ручные теги сохраняются; пустой итог, исключённые группы и повторно обработанный итог пропускаются.

Смена участников, обработка закрытия задач, запись заголовка/итога/комментария, уведомления и проверки по расписанию отключены. Точки запуска закомментированы; функции сохранены. Старые `/ai-preview`, `/ai-preview/status`, `/open-tasks-check`, `/open-task-eligibility`, `/time-check`, `/time-entry-baseline` возвращают 404. `/ai-test` теперь открывает массовое тегирование.

TAGGING.md содержит историческую документацию исходного проекта; актуальное поведение описано здесь. opencode.jsonc — исходный локальный конфиг, для запуска сервера не требуется.
