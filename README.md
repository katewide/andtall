# andtall — установка хэштегов задач

Код перенесён из AItags-main. Активен только сценарий установки тегов при изменении `UF_TASK_SUMMARY` через `POST /webhook` (событие `ONTASKUPDATE`, проверяется `auth.application_token`).

Смена участников, обработка закрытия задач, запись заголовка/итога/комментария, уведомления и проверки по расписанию отключены: точки запуска закомментированы в server.js. Их функции сохранены для возможного восстановления. Старые маршруты `/ai-test`, `/ai-preview`, `/ai-preview/status`, `/open-tasks-check`, `/open-task-eligibility`, `/time-check`, `/time-entry-baseline` возвращают 404.

## Запуск

Node.js 20+; `npm install`, затем экспортировать переменные из `.env.example` с реальными значениями и выполнить `npm start`. Файл .env автоматически не загружается. BASE_URL — адрес API-адаптера, используемого исходным приложением, а не адрес портала Битрикс24.

`GET /` — проверка доступности, `GET /debug` — диагностика (доступ ограничивать на уровне инфраструктуры). `npm test` — автономные тесты с подменой внешнего API.

## Поведение тегирования

Используются исходные AI-промпт и справочник task-taxonomy.json. Сценарий читает задачу и контекст, классифицирует их и записывает только поле тегов. Ручные теги сохраняются; запись проверяется повторным чтением. Пустой итог, исключённые группы и повторно обработанный итог пропускаются. Изменившийся во время анализа итог блокирует запись устаревшего результата.

Массовая обработка существующих задач пока не запускается и отдельный массовый endpoint не добавлен. Для него нужно определить список задач или фильтр отбора. Текущий webhook реагирует на изменение итога, а не сканирует все задачи.

TAGGING.md содержит историческую документацию исходного проекта; описание закрытия задач и preview в ней относится к отключённым сценариям. opencode.jsonc сохранён как исходный локальный конфиг и для запуска сервера не требуется.
